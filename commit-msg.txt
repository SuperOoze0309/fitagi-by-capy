Stop answering a native storage failure with an empty database

DS-01 was only half fixed: the adapter stopped calling isDBExists before
createConnection, but createAdapter() still caught every SQLite failure, logged a
warning and continued into IndexedDB. On a phone that means the workouts are in
SQLite, the app shows an empty log, and anything recorded next goes into a second,
invisible database. The reviewer reproduced exactly that with an injected open
failure; re-running the same probe now yields booted=false with the original row
still on disk.

createAdapter() no longer switches backends. SQLite is what a native build stores
its data in, IndexedDB is what a browser stores its data in, and a failure to open
either one is a startup failure: the splash screen explains it and offers a reload.
The single retry stays, because a reload can begin before the previous page has
finished upgrading and an open is then blocked until the old connection goes away.
The storage-failed message now says the log is still on the device and warns against
clearing app data, in all three languages.

Two smaller corrections from the same review:

- isAlreadyConnected() required only the phrase "already exists", so any unrelated
  error carrying it would have been swallowed. It now requires the database name too;
  an unrecognised message stays a real failure.
- The test double conflated registering a connection with creating the database file.
  The native side registers a Database object and only calls openOrCreateDatabase
  from open(), so the fake now creates the file on open() and exposes
  seedExistingDatabaseFile() to model a phone that already has one. That distinction
  is what makes "is this a fresh install?" answerable at all, so SqliteAdapter asks
  isDBExists between the two and records hasExistingDatabase().

New: src/test/storageBoot.test.ts drives the real entry point (initStorage, no
injected adapter) with SQLite open and schema failures -- the boot rejects, no
fallback is announced, the stored workout survives, and a later boot reads it back.
283 -> 292 tests across 56 suites.
