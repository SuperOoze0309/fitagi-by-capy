# FitAGI by Capy

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Version](https://img.shields.io/badge/version-1.0.0-informational.svg)](CHANGELOG.md)
[![Platform](https://img.shields.io/badge/platform-Android%206.0%2B-3ddc84.svg)](#支持的设备)
[![Tests](https://img.shields.io/badge/tests-361%20passing-brightgreen.svg)](docs/DEVELOPING.md#验证)

FitAGI by Capy 是一款免费、开源的健身记录应用，支持训练、饮食、计划和提醒。主要面向 Android，也可以在浏览器中运行。

应用以本地存储为主，不需要注册账号，没有广告或行为追踪。手动记录和查看历史不需要网络；AI 功能默认关闭，可按需连接你自己的模型服务。

希望它能让记录训练这件事简单一点：开始训练，添加动作，记下每组数据，之后随时查看自己的进步。

> 当前仍处于开发阶段。浏览器流程和自动化测试已验证，APK 尚未在真机或模拟器上验证。使用前请阅读[已知限制](#已知限制)。

## 下载 APK

在 [GitHub Releases](https://github.com/SuperOoze0309/fitagi-by-capy/releases/latest) 下载 `FitAGI-by-Capy-1.0.0.apk`，传到 Android 设备后打开安装。应用不经由应用商店分发，安装时可能需要允许对应应用安装未知来源的应用。

从 1.0.0 起，发布包是使用项目正式密钥签名的 release 构建；0.9.0 是调试签名的 debug 构建。**由于签名不同，1.0.0 无法直接覆盖安装在 0.9.0 之上。** 升级步骤：在 0.9.0 的“备份与恢复”中导出 JSON 备份，卸载 0.9.0，安装 1.0.0，再恢复备份。API Key、饮食照片和聊天记录不包含在备份中，不会随之迁移。此后使用同一密钥签名的版本可以直接覆盖升级。这一升级流程同样尚未在真机上验证，见[已知限制](#已知限制)。

发布包与仓库最新代码可能存在差异。各版本的变化见 [更新记录](CHANGELOG.md)，从源码构建的方法见 [开发指南](docs/DEVELOPING.md#中文)。

## 支持的设备

| 项目 | 说明 |
| --- | --- |
| Android | 工程配置最低版本为 Android 6.0（API 23），目标版本为 API 35；实际设备兼容性待验证 |
| 屏幕 | 支持手机和宽屏布局，宽屏使用侧边导航 |
| 相机与相册 | 用于选择饮食照片，不影响手动记录 |
| 通知 | 用于本地提醒；Android 13 及以上需要通知权限 |
| 网络 | 手动记录、历史和本地总结可离线使用；调用模型服务需要网络，或可访问的本地端点 |
| 存储 | Android 使用 SQLite，浏览器使用 IndexedDB；占用随记录和照片数量增加 |
| 界面语言 | 简体中文、英文、西班牙文，可手动选择或跟随系统 |

## 目前可用的功能

### 训练记录

- 创建训练，或继续尚未完成的训练草稿。
- 自定义动作名称，记录重量、次数、休息时间、RPE（主观用力程度）和 RIR（剩余可完成次数）。
- 标记热身组、力竭组和递减组，调整动作顺序，设置超级组。
- 复制上一组的数据，添加备注和平均心率。
- 查看训练时长，完成后保存到历史；也可以确认后删除草稿。
- 使用 kg 或 lb 记录重量。切换显示单位不会改写历史数据。

### 快速记录

用一句话录入训练，例如：

```text
卧推 60kg 8次 4组 最后一组力竭
bench 80 8 8 7 6 rir2
倒蹬 577lb 8次 4组
深蹲 100kg 5x5
```

应用会先尝试离线解析；解析失败且 AI 已启用时，再请求模型。结果先显示为预览，可以修改动作和每组数据，包括 RIR，也可以取消选择部分组。确认后才保存。

无法解析的文字可作为训练备注保存。快速记录保存后会直接生成一条已完成的训练。

### 历史与进步曲线

- 按本地日期查看训练，搜索动作名称和备注。
- 编辑训练时间和备注，删除记录，或重新打开已完成的训练。
- 查看每个动作的训练历史、最佳组、总组数和个人纪录（PR）。
- 在最佳组重量和估算一次最大重量（1RM）之间切换曲线。
- 查看训练量及相对上次的变化。训练量按规范化后的公斤重量计算。

### 饮食记录

- 手动填写食物名称、份量、热量、蛋白质、碳水化合物和脂肪。
- 一餐可包含多项食物，营养总量由明细汇总。
- 按日期查看记录和每日合计，搜索名称、备注或食物明细。
- 可附加相机或相册照片，照片压缩后保存在本地。
- 配置支持图片的模型后，可根据照片估算营养，再通过文字补充或修正。

**AI 分析结果是估算值。** 可以在保存前编辑；尚未确认的草稿不会写入记录。饮食照片不包含在备份中。

### 训练计划与提醒

周计划可以安排训练日和休息日，填写动作、组数、次数范围和目标重量。同一时间只启用一份计划，首页会显示当天安排，并支持从计划开始训练。删除计划不会删除已有训练。

提醒支持训练、饮食、喝水、称重、休息和自定义类型，可选择时间和重复日期，使用本地通知。AI 可辅助起草计划和提醒，均需确认后保存。原生通知的实际调度与撤销仍有待验证，详见[已知限制](#已知限制)。

### 个人资料

可选填昵称、性别、年龄或生日、身高、体重、目标体重、训练目标和活动水平。所有字段都可以留空，资料保存在本机。

饮食分析可附带一段简短的资料上下文，资料页可以预览实际发送的内容。性别信息仅用于 AI 上下文，不影响主题或界面。身高和体重统一按厘米、公斤存储，公制与英制只影响输入和显示。

### 训练总结与异常值提示

每日、每周和每月总结在本机生成，包括主要动作、训练次数、组数、训练量和变化趋势，不依赖模型。可以从历史重建，也可以选用 AI 润色后恢复本地原文。删除总结不会删除训练。

保存前，应用会参考已有历史，对明显异常的重量给出提示。你可以修正，也可以保留原值；应用不会自动替换数据。

### 动作别名

可以管理自己的命名规则，例如将 `bench` 统一为 `Bench Press`。规则不区分大小写，较长匹配优先，也优先于 AI 建议。

别名只影响之后的新记录，已有训练保留原始名称。

### AI 助手

AI 默认关闭。启用时，需要填写兼容 OpenAI 接口的服务地址和模型名称；需要认证的服务还需填写 API Key。

| 角色 | 用途 |
| --- | --- |
| 记录员 | 辅助解析和查询训练记录 |
| 提醒员 | 回顾近期训练数据和变化 |
| 教练 | 根据记录提出建议，提示词要求区分记录事实与建议 |

聊天支持流式显示、停止生成和历史加载重试。离开页面会取消当前请求，未完成的回答不会加入聊天记忆。一次请求的总时限为两分钟。

- Enter 发送，Shift+Enter 换行；确认中文输入法候选词不会触发发送。
- 本机最多保存最近 100 轮对话，追问时最多附带前 8 轮。
- 根据问题附带当前训练、相关动作的近期记录，以及近期训练总结；回答下方会说明发送的上下文。
- 可直接请求总结近期训练，也可以清空本机聊天历史。
- 聊天记录不包含在备份中。

饮食照片分析使用同一模型端点。应用会结合模型名称规则、手动设置和接口返回判断图片支持情况，但这些判断不能替代真实端点验证。AI 回答及估算说明按模型返回的原文显示。

### 备份与导出

| 格式 | 用途与范围 |
| --- | --- |
| JSON | 备份和恢复训练、规则、总结、饮食、提醒、计划、设置及已填写的个人资料 |
| Markdown | 便于阅读和分享的训练记录 |
| CSV | 每行一组，包含原始显示重量和规范化的公斤重量，便于表格分析 |

导入前会校验文件，并显示内容和替换范围，确认后才恢复。Markdown 和 CSV 支持全部时间、本月或最近 7 天；CSV 会处理可能被表格软件识别为公式的文本。

**备份不包含 API Key、饮食照片或聊天记录。** 恢复到同一 AI 端点时保留设备上的 Key；端点变化时清除 Key 并关闭 AI，需要重新配置。

恢复目前使用内存补偿回滚，尚不具备跨集合的持久化原子性，无法保证进程中断后完整恢复。重要数据请保留独立备份。

### 设置与外观

支持切换语言、默认重量单位，以及布偶猫、兔子、熊猫、虎鲸四套主题。每套主题有对应的配色、像素吉祥物和装饰图案。

手机使用底部导航，宽屏使用侧边导航。应用图标使用手绘布偶猫素材；素材来源和生成方法见 [设计说明](design/README.md)。

## 隐私

应用没有项目服务器、账号系统、云同步或行为追踪，记录保存在当前设备上。

只有你主动使用 AI 功能时，应用才会向配置的模型端点发送相应内容，包括聊天问题及选取的训练上下文、最近的部分对话，或饮食照片与个人资料上下文。起草计划和提醒时，也会使用相关的训练目标、活动水平等信息。数据发送后由所选服务处理，其保存与使用方式取决于该服务。

API Key 保存在本机，不写入备份。饮食照片和聊天记录同样不包含在备份中；更换设备后不会通过 JSON 备份恢复。

## 已知限制

- **APK 尚未在真机或模拟器上验证。** 浏览器与自动化测试通过，不等于 Android 实机验证通过。SQLite 适配器的测试使用模拟插件，实际冷启动和迁移仍待验证。
- **原生交互尚未验证。** 未在设备上打开分享面板、文件选择器、相机或相册，也未验证状态栏配色、硬件返回键和通知实际弹出。
- **尚未连接真实模型。** 文本与图片接口使用模拟响应测试，真实服务的兼容性、流式行为和图片支持仍待验证。
- **数据恢复与清理仍有待完善。** 备份恢复尚不具备持久化原子性；完整数据清空、多日通知撤销、训练自动保存与完成/丢弃操作的协调仍有遗留问题。设置页的“删除全部本地数据”目前不能视为完整清除保证。
- **图标效果尚未在真实启动器上验证。** 不同设备的裁切形状可能影响显示。
- 浏览器冒烟检查需要 Chrome 或 Edge。缺少浏览器时脚本会跳过，即使退出状态为成功，也不能视为已完成检查。

本轮修复、验证范围和未完成事项见 [调试记录](notes/debug-2026-10-04.md)。

## 开发与贡献

从源码运行、构建 APK 和执行检查的方法见 [开发指南](docs/DEVELOPING.md#中文)。

提交改动前请运行 `npm run verify`，包含代码规范、类型检查、单元测试和生产构建。当前测试规模为 **361 项、72 个套件**；浏览器检查覆盖手机和桌面两种视口。测试和浏览器检查请依次运行。

贡献时请注意：

1. 界面文案统一放入英文、简体中文和西班牙文翻译目录。
2. 存储变更须维护旧数据兼容，补充迁移测试，并同步两种存储实现。
3. 保留下面四个数据标识，避免已有记录或备份无法识别。

| 标识 | 用途 |
| --- | --- |
| `fitness-agent-backup` | JSON 备份格式标记 |
| `fitness-agent` | IndexedDB 数据库名 |
| `fitness_agent` | Android SQLite 数据库名 |
| `app.fitnessagent.tracker` | Android 包名 |

产品名称已从 Fitness Agent 改为 FitAGI by Capy，但以上标识保持不变。用户可见的导出文件使用 `fitagi-*` 名称。

```text
src/
  domain/        数据类型、单位、日期与训练指标
  storage/       IndexedDB 与 SQLite 适配器
  repositories/  训练、饮食、计划、提醒、资料与聊天等数据访问
  services/      备份、导出、图片处理、AI 与训练总结
  pages/         应用页面
  components/    共用界面组件
  state/         应用状态与偏好设置
  i18n/          三种语言的翻译目录
  theme/         主题与像素图案
  styles/        界面样式
  dev/           浏览器冒烟检查
  test/          单元测试与存储替身
android/         Android 工程
docs/            开发与架构文档
design/          图标素材与生成脚本
scripts/         开发与检查脚本
```
