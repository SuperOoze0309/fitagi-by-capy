# FitAGI by Capy

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Version](https://img.shields.io/badge/version-0.9.0-informational.svg)](CHANGELOG.md)
[![Platform](https://img.shields.io/badge/platform-Android%206.0%2B-3ddc84.svg)](#支持的设备)
[![Tests](https://img.shields.io/badge/tests-292%20passing-brightgreen.svg)](docs/DEVELOPING.md#验证)

面向 Android 的免费开源训练与饮食记录应用，本地优先。吉祥物是一只布偶猫，用代码画出来，不打包任何图片。

- **不要账号，不连服务器，不搞云同步，没有广告，没有埋点。**
- 核心功能全部离线可用。
- **AI 是可选项。** 关掉它，这仍是一套完整的训练记录工具；AI 只是在上面加点便利。

记录体验追求的是*备忘录加训练日志*的手感：打开，记一组，关掉。计划内的功能已经做完（0.9.0）：手动记录、本地存储、历史、带进步曲线的动作历史、kg/lb、可拍照分析的饮食记录、以本地通知实现的提醒、每周训练计划、可选的纯本机个人资料、四套配色主题（手绘像素吉祥物加对应景物）、完整界面翻译（简体中文、英文、西班牙文）、JSON 备份恢复、Markdown/CSV 导出、用户自己的别名规则、带预览确认的自然语言快速记录、异常值复核、多层总结，以及可选的 OpenAI 兼容 AI 层。

> **第一次来？** [目前可用的功能](#目前可用的功能) 是功能导览；[已知限制](#已知限制) 老实交代哪些**还没**验证过——目前没在任何真机上跑过。

## 下载 APK

到[最新 Release](https://github.com/SuperOoze0309/fitagi-by-capy/releases/latest)下载 `FitAGI-by-Capy-0.9.0-debug.apk`，拷进手机直接点开安装。系统会拦一下「安装未知来源应用」，放行即可——这个包用的是 Android 调试签名，不是 Play 签名。也可以用 `adb install -r FitAGI-by-Capy-0.9.0-debug.apk`。

这个 APK 能干什么，一口气说完：一组一组记录训练，记饮食（可选拍照分析），看进步曲线，用本地通知提醒你该练了，安排每周训练计划，还能选配一个你自己填的 OpenAI 兼容端点。**你不主动发起 AI 请求，数据就不出手机。** 没有账号、没有服务器、没有广告、没有埋点，飞行模式下核心功能照常用。

## 支持的设备

| | |
| --- | --- |
| Android 版本 | **6.0（API 23）起步。** 针对 API 35 编译并校验 |
| 处理器架构 | 不限。手机平板都行，ARM 或 x86，32 位 64 位都行 |
| 屏幕 | 320dp 的小屏手机到平板、甚至接近桌面宽度的窗口都能用。布局自动重排，不挑尺寸 |
| 相机 | **可有可无。** 没相机的设备照样装、照样手记饮食，相机只服务于拍照分析 |
| 通知 | 提醒要拿到 Android 13+ 的通知权限才会响，不给权限就只是不响。重启手机后提醒依然有效 |
| 占用 | 几 MB。数据就是一个 SQLite 文件，再加上你自己拍的饮食照片 |
| 网络 | **只有可选的 AI 功能要用。** 其余部分完全离线 |
| 语言 | 简体中文、英文、西班牙文；其余语言跟随系统，回退英文 |

## 目前可用的功能

**首次启动**
- 全新安装先走两步权限引导：先是相机与相册，再是通知。每一步在弹系统授权框之前都说清这个权限*用来做什么*，两步都能拒绝，拒绝也不会卡住任何功能
- 引导之前装的旧版本会跳过这一步，升级不会再来问你一遍

**提醒**
- 通知由手机本地调度，不经过服务器。设一个时间点，配上任意几个星期几，或者每天
- 六种类型（训练、饮食、喝水、称重、休息、自定义），差别只在标签文案和点击后跳去哪
- **手动加也行，让 AI 按你的目标、活动水平和实际训练时间推荐 3～5 条也行**。挑中哪几条，就以可编辑的提醒建出来
- 每次启动都照列表重建一遍调度。重启手机、恢复备份、或者晚点才给权限，都不会让两边对不上
- 数据哪儿也不发。通知在本机生成

**训练计划**
- 一份周计划：七天，每天写训练名称、动作、组数、次数处方（「8-10」「5」「AMRAP」，是文本不是数字）和可选目标重量
- 休息日也是计划的一部分，不是计划里空着的那格
- 同一时间只有一份计划处于启用状态。首页显示今天练什么，点「开始训练」就新建一次训练，动作已经带好了
- **让 AI 起草**：把想法说给它（「一周四天，上下肢分化，一小时左右」），它拟出一周安排先给你过目，你点了确认才落盘
- 计划不碰历史。删掉一份计划，按它记下来的每一次训练都还在

**首页**
- 开始训练，或者接着练没练完的那次
- 最近的训练，带组数、容量和时长
- 今天的饮食与热量合计，外加一键「记录一餐」
- 快速记录入口

**训练**——用得最多的那个界面
- 新建训练，立刻落盘，刷新页面回来还能接着记
- 动作名敲进去就能加动作，应用不内置动作库
- 快速加组，新组继承上一组的重量、次数、RPE、RIR 和休息
- 重量、次数、RPE 行内直接填数字，另有休息和 RIR
- 单组可以标记力竭、热身、递减组
- 复制上一组，复制任何一组，删组
- 调整动作顺序、标超级组、写备注、记平均心率
- 实时计时；「完成并保存」定格时长，这次训练进历史
- 完成弹层给三条出路：**继续训练**、**完成并保存**、**取消这次训练**。取消要确认，确认后草稿才删——这也是删草稿的唯一入口。标题栏那个「首页」按钮是故意把这训练挂起，方便回头接着练
- 重命名动作，并可一步**记住为别名规则**

**饮食**——关掉 AI 也能用的饮食记录
- 手动录入名称、份量、热量、蛋白质、碳水、脂肪、时间和备注，还能拆明细，每条食物各带各的数字。一餐的总量就是各明细项之和，标题上的数字和明细不会打架
- 照片来自相机或相册，在本机压一遍（最长边 1280 px，JPEG 质量 0.72），以 data URL 存进独立的键值存储，一餐一行。删掉这餐，照片一起删
- 配了支持视觉的模型，就能**用照片让 AI 估算**。结果以可编辑草稿给出，并标明这是估算不是实测；点「确认并保存」之前不写任何数据
- **修正对话**就地把估算改掉：「米饭大概 150 克」只重算那一项，不从头上再来，你没提到的项目原样留着。每条修正都走同一个可编辑表单
- 饮食记录按本地日期分组，每页 40 条。顶部卡片汇总今天的热量、蛋白质、碳水和脂肪，每一天显示当天的热量合计，搜索匹配记录名称、备注和明细项名称
- 照片**不进**备份。恢复后的一餐留着数字，丢掉图片
- 已知配的模型只吃文本时，应用当场说明，手动表单照常可用

**个人资料**——可选，只存在本机
- 昵称、性别、年龄或生日、身高、体重、目标体重、单位制（公制或英制）、训练目标和活动水平。每个字段都能留空
- 浓缩成一小段 `## User profile` 块，附在饮食分析请求上。让模型估算一餐，不等于要把整份历史发出去
- 资料页把这段块原样显示出来，跟实际发出去的内容一致
- **性别只当 AI 的上下文，没别的用处。** 它不影响主题、配色、图标、吉祥物，也不影响任何行为；有测试断言设置里不带 `gender`、资料里不带 `theme`
- 生日按本地日历日期解析，UTC 以西的时区不会让年龄差出一天

**快速记录**——自然语言，AI 可选
- 可以输入 `卧推 60kg 8次 4组 最后一组力竭`、`bench 80 8 8 7 6 rir2`、`倒蹬577lb 8次4组` 或 `深蹲 100kg 5x5`
- **离线解析器先跑**，不靠任何模型就能吃下这些输入；实在解析不了才去问那个可选的模型
- 结果永远是**预览**：每个动作、每一组都能改，能取消勾选某些组，确认之前没有任何东西进存储
- 什么都解析不出来时，这段文字会当训练备注留着，不会丢
- 快速记录存下的训练直接以已完成状态进历史，不会留一个开着没关的会话

**历史**
- 按本地日期分组，最新的在前，分页加载，攒了几年也不会变慢
- 搜索动作名和训练备注
- 点开一次训练，改开始/结束时间和备注，或者删掉它
- 已完成的训练能重新打开接着记，也能改回进行中
- 点任意动作名，打开它的完整历史

**动作历史**
- 最佳组、训练次数、总组数、PR 次数和最近一次训练日期
- **PR 徽章**标出每一次刷新最大重量的训练，并显示相对上一次的变化
- **进步曲线**带坐标轴标签和读数，可在**最佳组**和**估算 1RM**之间切换。换成后者，一个大重量三组和一个轻重量的十次组就能横向比了
- 按次列出记录，含组数、容量、估算 1RM，以及相对上一次的增减

**别名规则**
- 完整的管理界面：新建、编辑、删除、列表
- 记录过程中重命名动作时也会自动建一条（「bench」→「Bench Press」）
- 匹配不区分大小写，最长匹配优先
- 规则只影响*之后的新记录*。过去的训练保留你当时敲的原文
- 规则的优先级永远高于任何 AI 建议

**训练总结**——多层，本机生成
- **每日**：练了什么（「练了腿和肩。」）、主要动作及其数字（`Leg Press: 100kg × 8 × 4`）、训练次数、正式组数、容量、时间，以及相对自己此前最好成绩的明显变化（`+5kg vs before`）
- **每周**：由各天汇上来——训练次数、相对上一周的容量变化、主要动作，每天一行
- **每月**：由各周汇上来，一个月不是整月 JSON 堆一起
- **不依赖任何模型**，LLM 只能在事后改写措辞
- 在总结页能翻这三种粒度，还有个「重建」，从历史重新生成
- 启动时补齐当前和上一周/月缺的总结，导入进来的历史同样会被总结
- **用 AI 润色**（可选）只是改写文字。本机生成的文本一直留着，一键就能恢复；AI 关着时按钮写「润色（AI 已关闭）」，而不是消失
- 总结是派生数据。删掉一条总结，永远不碰它来自的那些训练

**异常值复核**
- 明显超出你自己历史范围的重量，保存前会被拦一下：弹层显示这个数值和你平时的区间，给**修正为**、**保持原样**、**忽略这条提醒**三个选择
- 它从不阻止保存，也从不改数字。你不输入替换值，`600 kg` 就还是 `600 kg`
- 结构化记录和快速记录都会过这套检查
- 攒够三次历史训练它才开口。早期不来烦你

**AI（可选，默认关闭）**
- 接任何 OpenAI 兼容端点，Base URL、API Key 和模型都由你填
- 三种角色，系统提示词各不相同：
  - **记录员**——管解析和查询，不给建议。
  - **提醒员**——你上次练了什么：重量、次数、RPE、趋势。
  - **教练**——可以给建议，但回答必须拆成已记录的 **FACTS** 和自己的 **SUGGESTION**。两段标题跟随你提问所用的语言；建议里的数字必须有你实际记录过的基线作依据；提到伤痛时它不做诊断，只让你停下这个动作并去看专业人士
- **是对话，不是表单**：回答从端点流式回来时逐字出现在屏幕上，气泡跟着变高，记录往下滚。输入框像聊天应用那样钉在底部，随输入内容长高到某个上限。你手动往上滚过的记录就停在你放的位置，不会被拽回底部
- 不理会流式开关的端点也能用，整段回答一次性出来，不会报错
- 会话里认出的动作名会一并带出
- **聊天记忆保存在本机**：离开再回来仍能看到最近最多 100 轮对话；追问时最多附带前 8 轮问答，帮助模型接上前文。每条回答会显示实际发送的上下文；「清空」会删除本机聊天记录。聊天内容不进备份。
- **总结近期训练**这个动作不需要提问，直接让它对已经搭好的上下文做一段回顾
- **上下文构建器**决定发什么：当前进行中的训练、你问到的动作最近 3～5 次训练、最近 7 天，以及周/月汇总。从来不是整个数据库。每条回答都会显示这次发了什么。
- AI 关着时，AI 页面说明怎么开，并指向离线的快速记录
- 报错都能处理：密钥被拒、Base URL 写错、主机连不上，各有各的具体提示
- **视觉能力是探出来的，不是猜的。** 模型名按已知家族归到 `supported`、`unsupported` 或 `unknown`，你也能在设置里改判。已知只吃文本的模型绝不会收到照片；`unknown` 允许你试一把，万一端点用一句自然语言拒绝，应用认得出来并告诉你这个模型不收图片，而不是甩一个原始 HTTP 错误
- 饮食的**照片分析**走同一个端点：图片以 OpenAI 兼容的 `image_url` content part 装在 data URL 里发出去，模型自己对不确定之处的说法原样显示在估算结果旁边（模型生成的文字从不翻译）

**备份与恢复**
- 导出一个能读的 JSON：训练、动作、组、别名规则、总结、饮食、提醒、计划和设置（单位、主题、语言、AI 端点、模型、视觉覆盖），资料填过也一并带上
- 饮食照片刻意不进去。备份是你数据的记录，不是照片堆。恢复后的一餐留着数字，没有图片
- API Key **绝不**写进备份，恢复也绝不覆盖设备上已有的 Key
- 导入前先校验文件，告诉你里面有什么、会替换掉什么，你确认了才动手。饮食、提醒、计划出现之前导出的备份照样能导入：里面的训练原样恢复，新的部分是空的
- **Markdown** 和 **CSV** 导出是给人看的：每个动作一张表，每组都有记录；CSV 一行一组，规范 kg 值和显示重量并排。CSV 单元格会加前缀，免得电子表格把输入的文字当公式执行。范围可以选全部时间、本月或最近 7 天。

**设置**
- 语言：**自动**（跟随系统）或简体中文 / English / Español，切了立刻生效，不用刷新。日期和时间格式跟着所选语言走
- 主题：四套内置——**ragdoll**（布偶猫，暖白配粉）、**bunny**（兔子，粉蓝）、**panda**（熊猫，黑白）、**orca**（虎鲸，深海蓝）。每套有自己的配色和 16×16 像素吉祥物，选择器里以色块加吉祥物展示。Android 上状态栏跟着主题走，图标颜色由状态栏底色推导，不按主题写死
- 默认单位（kg / lb）
- 显示当前用的存储引擎，不藏着
- AI：启用开关、Base URL、Key、模型、默认角色，以及探测到的视觉能力和覆盖开关
- 通往个人资料、备份与恢复、训练总结、别名规则的入口
- 删除全部本地数据（训练、饮食、总结、规则和资料）

### 单位

重量按你敲的数值加单位存下来，另外留一个规范 kg 值，供容量计算和比较用。切换显示单位不改写你的历史。

### 语言与主题

用户能看到的每一句文案都来自翻译目录：`src/i18n/en.ts` 是基准，`zh-CN.ts` 和 `es.ts` 按它的结构做类型检查，键漏了、拼错了就是构建错误，不会变成中文界面里冒出来一个英文单词。日期、时间和数字格式化统一走 `Intl`，用该语言自己的 locale 标签。模型生成的文字——AI 的回答、饮食估算自带的说明——原样显示，从不翻译。

一套主题就是一组颜色 token、一个像素吉祥物，**外加一组景物图案**。组件只认 token，样式表里没有自己的配色值，加第五套主题只是加一个 `ThemeDefinition`、一个 16×16 吉祥物精灵和几个图案，页面、组件、样式表都不用动。所有图形都是字符网格画出来的：应用里没有图片文件，没有 base64 数据块，也没有第三方素材，应用图标和启动画面一样如此。

四套主题：**ragdoll**（应用自己的猫，暖白纸感、灰毛、蓝眼、粉鼻）、**bunny**（粉蓝）、**panda**（黑白）、**orca**（深海蓝）。

| panda | 低矮的苔藓 | 一根竹子、一个爪印、一片叶子 | 一片叶子、一个爪印 |
| orca | 水面与浪尖 | 一条鱼、气泡、一颗星 | 气泡、一颗星 |

图案在运行时拼成一整条宽精灵图（`src/theme/scenery.ts`），画在首页主卡片底部和空状态里。三条规则让它安分当装饰：`aria-hidden`、从不接收点击、排列是确定的——同一套主题永远画出同一个场景。浏览器冒烟测试会比对三套主题场景的像素级指纹，「每套主题画自己的景物」是被断言过的，不是嘴上说说。

### 应用图标

启动图标就是那只手绘布偶猫，直接用原始素材：
`design/icon-candidates/source/cat-sketch.jpg`（413×358）。处理流程把它裁成 350×350 的正方形，整只猫留着，右边缘的心形和另一幅画的残片去掉，再从四角采样草图自己的纸张颜色（`#f9f5f2`），最后按各密度合成。

```bash
pwsh -File design/icon-candidates/render-android-icons.ps1   # launcher + adaptive layers
node design/icon-candidates/render-splashes.mjs              # splash, both orientations
```

有三个决定值得说：

- **这幅画放在自适应图标的*背景*层，不是前景层。** 草图是没透明通道的 JPEG，当前景用，它自带的白色方块会压在背景色上，接缝一眼就看见。放背景层满幅铺开，启动器遮罩裁掉的是纸，不是猫；`ic_launcher_foreground.png` 则是一张透明占位图。
- **猫占普通方形图标的 88%、圆形图标的 78%、自适应图层的 78%。** 自适应安全区是 108dp 中间那 72，圆形遮罩内切在里面；取 78%，耳朵、眼睛、鼻子就始终落在安全区内。圆形裁切的启动器会剪掉最外侧的胡须——草图是画到边的，不然猫看着就像缩在正中间。
- **这幅画进来时被压深了一点**（gamma 取 1.35）。它是一张很淡的铅笔稿，48px 下毛发和纸色糊成一团。Gamma 压暗中间调——毛发和轮廓线——近乎白色的纸面不动；换成对比度曲线就正好相反，会把浅灰毛发进一步推向白色。填充色随后从调整后的图上重新采样，平铺色块和裁剪边缘就对得上了。

`design/icon-candidates/preview-icons.png` 是结果在 Android 三种遮罩形状下的样子，`node design/icon-candidates/preview-icons.mjs` 可以重新生成。

`design/icon-candidates/alternates/` 里是一只和像素吉祥物同风格的矢量猫，最早的尝试，留着仅作参考。`uc-monogram/` 里是更早的字母造型方案。

### 布局

同一套布局要服务应用所处的任何屏幕。手机上是底部导航栏，56rem 以上换成侧边栏；字号流式（`clamp()`），栅格 `auto-fit`，内容有最大阅读宽度、空间够就居中，弹层在宽屏上变成居中对话框，而不是铺满一屏的面板。内容宽度没有写死的像素值，也不挑屏幕尺寸和方向。

### 圆角

界面是圆角物件搭起来的，不是切了角的矩形。全套圆角来自 `:root` 里的六个 radius token：

| Token | 用途 |
| --- | --- |
| `--radius-xs` | chip、分段按钮、对话气泡内侧的角 |
| `--radius-sm` | 输入框、横幅、内部区块、卡片里嵌套的卡片 |
| `--radius` | 卡片、动作卡片、主题磁贴 |
| `--radius-lg` | 卡片外圈、聊天气泡、文本输入框 |
| `--radius-xl` | 底部弹层的顶部 |
| `--radius-pill` | 所有按钮、徽章、开关和筛选 chip |

嵌套表面**往下**降一档（卡片用 `--radius-lg`，里面的元素用 `--radius-sm`），曲线才同心。嵌套盒子用同一个圆角，内侧看着会偏紧，就是不对。`src/test/theme.test.ts` 不检查这条，但 `global.css` 里没有任何字面量圆角值——界面上每个圆角都出自上面这张表。

### 数据模型一览

`Workout → ExerciseEntry[] → SetEntry[]`，一组带重量、次数、可选的时长、距离、休息、RPE、RIR，以及力竭/热身/递减组的标记。饮食另算一个聚合：`Meal → MealItem[]`，一餐的总量由明细项推出来。完整模型和取舍见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 已知限制

- **没在真机上跑过。** 这个环境里没有系统镜像，APK 没装到真机或模拟器上。SQLite 适配器的测试会通过伪插件跑它真实的 SQL，但设备上的第一次启动还是值得做一遍。
- **原生路径只过了类型检查，没真跑过。** 分享面板和文件选择器（`services/fileTransfer.ts`）照 Capacitor 的 `@capacitor/share` 和 `@capacitor/filesystem` 定义写的；相机/相册选择器（`services/imageInput.ts`）是带 `capture="environment"` 的平台文件输入，Android WebView 会把它接到系统选择器上。硬件上没弹过任何原生对话框。它们周围的浏览器降级路径在冒烟测试里跑过，但无头页面驱动不了原生对话框，那一轮是直接通过仓储写入饮食照片，没走选择器。
- **两个 Android 外壳集成同样没在硬件上验证。** `services/nativeShell.ts` 按当前主题给状态栏上色，并接管硬件返回键（先关弹层 → 再返回上一页 → 起始页才退出）。两者都有 `Capacitor.isNativePlatform()` 挡着，浏览器里不生效；状态栏那套*判断逻辑*有单元测试，但没人在设备上见过它工作。
- **没调用过真实模型。** 这个仓库从没连过任何 LLM 或视觉端点：OpenAI 兼容客户端是对着 mock 的 `fetch` 测的，饮食分析由注入 chat 函数的测试覆盖。某个端点到底收不收 data URL 图片，只能靠能力规则和识别端点的拒绝来验证，没有真实请求为它背书。
- **启动图标没在真实启动器里看过。** 素材是在 48、96、192 px 下渲染出来用眼睛验的，自适应前景也按文档给的安全区缩放过；但某台手机到底用哪种遮罩（圆形、圆角方形、方形），状态栏颜色挨着真实的 Android 主题是什么效果，目前只能从平台规则推。
- 浏览器冒烟测试要装 Chrome 或 Edge；没有的话 `npm run test:browser` 会提示跳过，并以成功状态退出。

## 应用改名：哪些标识被冻结

产品名在 0.8.0 从 *Fitness Agent* 改成了 *FitAGI by Capy*。有四个标识刻意**没**跟着改，因为它们决定既有数据怎么被找到，跟应用怎么介绍自己无关：

| 冻结值 | 位置 | 原因 |
| --- | --- | --- |
| `fitness-agent-backup` | `services/backup.ts` | 识别备份文件的标记。改掉它，用户已经导出的每一份备份都会被拒。 |
| `fitness-agent` | `storage/idbAdapter.ts` | IndexedDB 数据库名。改掉它会悄悄打开一个全新的空库。 |
| `fitness_agent` | `storage/sqliteAdapter.ts` | Android 上的 SQLite 文件名，同上。 |
| `app.fitnessagent.tracker` | `capacitor.config.ts`、`build.gradle` | Android 包名。换一个会装出第二个应用，第一个应用的数据留在原地。 |

用户看得见的文件名——备份、Markdown 和 CSV 导出——倒是真改了：`fitagi-2026-02-14-0931.json`、`fitagi-2026-03-04.md`、`fitagi-2026-03-04.csv`。那些是标签，不是键：旧文件照样能恢复，格式是从内容判断的。

## 出问题时怎么办

渲染出错时弹的是恢复界面，不是白屏，用的是你选的语言，并且明确告诉你数据没被动过。要是反复出现，打开数据页（在地址后面加 `#/data`）导出一份 JSON 备份——那才是能恢复的格式。

## 本阶段不包含

几个能接进现有结构的想法：定时重建每周总结、在力量曲线旁边加一条按动作的容量曲线、一个用来对照当天摄入的营养目标，还有进度照片。都不用改架构。

## 隐私

数据全在这台设备上。没有项目服务器，没有账号，没有埋点。应用唯一可能发出的网络请求，是发往*你*配置的 OpenAI 兼容端点，而且只在你主动点 AI 功能时才发。聊天记录保存在本机；每次提问会把最近最多 8 轮对话和这次训练上下文发给所选端点，回答下方会列出实际发送的段落。聊天记录不进备份。饮食照片只在你发起的那次分析请求里发送，不会传到别处，就留在应用自己的存储里。个人资料只存本机，只有作为附在饮食请求后面的那一小段上下文时才会到模型手里。备份里永远没有你的 API Key，也没有饮食照片。

## 参与贡献

最要紧的两条规矩：

1. **组件里不许出现面向用户的字符串。** 每条文案都在 `src/i18n/en.ts` 和它的两份翻译里；目录不完整，或者某句话是从英文照抄的，`src/test/i18n.test.ts` 都会让构建失败。
2. **绝不丢用户数据。** 结构变更只做增量，迁移补默认值，旧版本写出的文件仍然能导入。上面那四个冻结标识就是为这条存在的——别改它们的名字。

提交 pull request 之前先跑 `npm run verify`：lint、类型检查、292 个单元测试、生产构建。`npm run test:browser` 还会在无头 Chrome 里按两种视口驱动真实应用。其余内容在 [`docs/DEVELOPING.md`](docs/DEVELOPING.md)。
